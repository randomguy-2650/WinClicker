WinClicker is an open‐source project, and we welcome contributions from everyone. Please check the guidelines below on how to report issues or submit code.

## 📡 Using the issue tracker

The [issue tracker](https://github.com/randomguy-2650/WinClicker/issues) is for bug reports, accessibility issues, feature requests and pull requests exclusively. We want you to follow these guidelines when using the issue tracker.

- Please **do not** use the issue tracker for personal support requests. Use [Discussions](https://github.com/randomguy-2650/WinClicker/discussions/categories/support) instead.
- Please **do not** derail, hijack or troll issues. Keep the discussion on topic and be respectful of others.
- Please **do not** post comments with **+1** or **👍**, as that will spam the comments section with irrelevant comments. Use [reactions](https://github.blog/2016-03-10-add-reactions-to-pull-requests-issues-and-comments) instead.
- **Do** use the issue tracker for bug reports, accessibility issues, feature requests and pull requests.

Issues that do not follow these guidelines are subject to closure. There simply aren’t enough resources for maintainers and contributors to troubleshoot personal support requests.

### 🐛 Bug reports

A bug is a _demonstrable_ problem caused by code in WinClicker. Bug reports are an important contribution to the quality of the project. When submitting a bug report, there are a few steps you can take to make sure your issues get attention quickly.

- Please **do not** paste in large blocks of irrelevant code.
- **Do** search for an existing issue before creating a new one.
- **Do** explain the bug clearly and concisely.
- **Do** provide additional information when necessary to replicate the bug.

### 💡 Feature requests

Feature requests can be added using [Discussions](https://github.com/randomguy-2650/WinClicker/discussions/categories/ideas).

- **Do** search for an existing feature request before suggesting a new feature.
- **Do** use the voting buttons to vote for a feature.
- Also share substantial use cases and perspective that support new features if they haven’t already been mentioned.
- And as always, **never** bump, spam or ping contributors to prioritise your own feature.

### 🔀 Pull requests

- Please **do not** submit a PR if you don’t create a new branch for that feature. It will mess up the commit history for the next PR.
- **Do** make sure your PR clearly defines what you’re changing. Even if you feel your changes are obvious, please explain them so other contributors can more easily review your work. PRs without detailed descriptions are subject to closure pending more details.
- Also open your PR against the `main` branch.

The maintainer reserves the right to reject any PR that’s outside the scope of the project or doesn’t meet code quality standards.

## 📖 Documentation

Maintaining good documentation can be a painstaking task, but poor documentation leads to frustration and makes the project less appealing to users. Fortunately, writing documentation for WinClicker is fast and easy!

If you need help with documentation, feel free to reach out in the [Discussions](https://github.com/randomguy-2650/WinClicker/discussions/categories/support).

### GitHub Flavored Markdown

GitHub renders Markdown according to the [GFM spec](https://github.github.com/gfm). You can use any Markdown feature available in the GFM spec, although we don’t recommend complex ones that don’t render properly in other Markdown renderers.

## ♿ Accessibility

WinClicker is built with accessibility in mind. Building user interfaces that are fully accessible to users with varying capabilities across a multitude of circumstances is a daunting challenge. Oftentimes, the solution to an accessibility problem is not written in black and white, and therefore, we may not get it right the first time around. There are, however, guidelines we can follow in our effort to make WinClicker an accessible app.

We take this commitment seriously, so please ensure your contributions have this goal in mind. If you need help with anything accessibility‐related, please reach out to the community for assistance. If you discover an accessibility concern within WinClicker, please file an accessibility issue on the [issue tracker](https://github.com/randomguy-2650/WinClicker/issues/new?template=accessibility.yaml).

It’s important to remember that, although accessibility starts with basic UI elements, it doesn’t end with them. It’s everyone’s responsibility to encourage best practices and ensure we’re providing an optimal experience for all of our users.
